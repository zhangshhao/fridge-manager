# 业务与接口

## 范围及流程

本机实施对应原方案 P01—P06 的源码和自动化部分。四个入口为冰箱、今天吃什么、做菜记录、我的。确认做菜为独立工作页面。未实现照片、扫码、购物清单、系统推送、多冰箱和离线同步。

入库：标准名称/别名 → 基准单位 → 新批次 → 入库流水。

做菜：推荐或手动草稿 → 多菜品实际用量 → 整餐事务内校验 → 批次扣减 → 快照、记录及流水。提交失败整餐回滚。已归档项不能消耗。未入库食材不关联库存。

批次顺序：到期日升序（空值最后）、入库时间升序、批次 ID。默认排除已过期；用户可明确选择包含过期。实际使用批次支持按单道菜用料指定。没有包装换算配置时拒绝跨维度单位，不猜重量。

## 数据保证

数量接口为字符串，Zod 限制输入到 3 位小数，PostgreSQL `numeric(15,3)` 精确保存，前后端计算使用 Decimal。批次有非负 CHECK 约束，所有库存更新必须同时写 Ledger。核对脚本计算每批次流水总和是否等于余额。

家庭行锁覆盖全部库存事务。相比细粒度锁，家庭内操作会短暂排队，适合最多 5 人的首版且简化死锁防护。事务内重新验证成员关系，再读取全部用料涉及批次；同食材重复使用时前一道菜写入对后一道可见，任何不足回滚整餐。Prisma 对事务冲突最多尝试 3 次。

修改数据必须携带幂等编号（邀请、会话、偏好等非库存接口除外）。同一家庭同一编号有唯一约束，摘要包含操作人、URL、内容；相同重发返回原结果，不同内容返回 409。做菜修改额外携带 `revision` 防止覆盖他人更新。冲回流水的 `reversalOf` 唯一，撤销本身检查状态。

历史用料保留名称、单位、数量、步骤快照，流水保留批次、操作人名称、变化原因；Audit 保留每次已成功提交的记录版本。撤销、归档不删除历史。数据维护删除家庭时使用外键级联清除该家庭。

## HTTP 约定

同源 `/api`。Cookie `session` 为随机 256 位令牌，数据库只存 SHA-256 摘要。生产 Cookie 使用 Secure、HttpOnly、SameSite=Strict。读写家庭数据均需 `x-family-id`，服务器独立检查成员关系。所有修改请求 Origin 必须等于 APP_ORIGIN，绝不接受缺失来源。响应 `Cache-Control: no-store`。

库存写接口头 `Idempotency-Key` 为 16—100 位字母/数字/下划线/横线，推荐 UUID。错误结构 `{message,details?,requestId?}`；401 重新登录、403 无权限、409 库存/版本/幂等冲突、429 限额、502 AI 无效输出、503 AI 未配置。

## 本地菜谱匹配

内置 HowToCook 的固定版本，331 道菜保存在 API 源码 `data/recipes.json` 并随构建分发。接口沿用家庭成员校验和 Origin 检查，不增加数据库表或迁移，不计入 AI 限额，不写库存。

`/recipes/recommend` 接收 servings、minutes（0 表示不限）、taste、avoid、query、category、scope（inventory 默认按库存推荐，all 浏览全库）、readyOnly、offset、limit（1—24）。返回 recipes、total（当前结果数）、catalogSize（全库总数）、offset、hasMore。菜谱包含来源、原文用量、步骤、分类、时长（未注明为 null）、匹配的库存 ID 和原单位、可用数量、缺料及临期标记。

排除过期、零库存、归档项；食材名称和别名采用精确归一化匹配，不做子串替代或猜测包装重量。家中常备调料参与种类匹配。inventory 范围至少命中一种库存主料；all 范围允许没有库存匹配的菜谱，仍保留搜索、分类、时间、忌口和 readyOnly 筛选。先按种类齐全，再按主料覆盖率、缺料数和临期食材排序，使用稳定 ID 分页。时间上限排除未注明时长的菜谱。家庭忌口与本次忌口合并，原用料、做法、小贴士和常见食材别名都参与过滤；仍需人工核对隐含过敏原。

本地菜谱进入记餐时数量留空，用户填写实际用量，复用现有整餐事务及幂等扣减。推荐阶段不扣库存。

## AI 校验与限额

仅发送允许使用的食材标识、名称、单位、可用量及用餐偏好，不发送用户、密码、会话或邀请。过滤名称/别名命中已知忌口的食材；校验返回 JSON、3 道菜、引用、原单位、十进制数量、每道菜合计库存和文本中已知忌口。忌口校验以字符串为基础，不能保证识别所有隐含过敏原，界面提示人工复核。

缓存包含家庭、库存版本、偏好、日期、模型，有效期 5 分钟。用户/家庭每日默认 20/50 次，按上海时间计算，失败调用也计数；并发保留额度时锁定用户和家庭。AI 并发默认最多 2，25 秒超时，3500 输出 token，单请求 64KB，上游不可用不自动重试。生产部署固定一个 API 实例；若扩多实例需将并发控制迁移到共享存储。

API JSON 日志不记录请求体、Cookie、授权密钥或查询参数。记录模型、请求标识、状态及耗时；供应商用量写入 AiCall。建议家庭设置里不填写无关个人信息。
